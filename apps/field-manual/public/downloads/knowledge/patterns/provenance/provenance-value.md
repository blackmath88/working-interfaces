## Purpose

A provenance value shows that information originated elsewhere and keeps its source inspectable.

It is useful when a value is carried forward from another stage, imported from evidence, generated by a calculation, or changed through a later correction.

## Keep

- The current value remains easy to read.
- Its origin is visible without requiring guesswork.
- The user can inspect the source without losing the current workspace.
- Corrections add history rather than silently replacing it.
- Provenance is available as text, not only as an icon or color.

## Avoid

- Showing lineage for trivial values with no decision relevance.
- Turning every field into an audit-log interface.
- Hiding source information in a tooltip that is unavailable by keyboard.
- Treating AI-generated information as authoritative without attribution.

## Open questions

- Should source details open inline, in an inspector, or by navigation?
- How much history belongs in the default view?
- How should superseded values be summarized on mobile?
- Which provenance types need distinct language or symbols?
