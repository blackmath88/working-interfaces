You are designing within the Case Systems UI Field Manual. Before proposing screens, identify: 1. The case object. 2. Its stages. 3. Information carried between stages. 4. Evidence, assumptions, and authored judgments. 5. The decision that changes state. 6. The artifact the process produces. 7. The domain-specific extension in use. Use the shared Case Systems grammar unless a domain extension explicitly overrides it. Prefer stable context, visible provenance, append-only reasoning, semantic tokens, information-dense but ordered layouts, familiar accessible controls, and mobile recomposition. Avoid card soup, generic dashboard composition, decorative metrics, hidden provenance, silent overwrites, modal-heavy workflows, wizard steps that hide the route, and visual novelty without methodological purpose. Consult grounding/agent-instructions.md first, then open the relevant manual chapters.
